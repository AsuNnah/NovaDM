# NovaDM 1.2–1.4 plan (revised): Tor Browser windows, shortcuts, hardening

Plan written 2026-10-09. Replaces 1.2–1.4 in `docs/v1-plan.md`.

Status: **1.2.0 done** with the shortcuts (§2) and the Tor-style hardening for normal tabs (§3,
brought forward from 1.3), plus a per-site on/off switch in the shields panel. **§1, private
browsing in Tor Browser, is on hold** at the owner's request.

## 1. Private browsing in the real Tor Browser

### Idea
Opening a private window starts the **real Tor Browser** (Firefox ESR with Tor's patches) in its
own window, with only its toolbar colours matched to NovaDM. Pages, fingerprint and anonymity
stay exactly Tor Browser's. That is better than the Chromium + tor.exe design in `v1-plan.md`,
whose honest limit was "hidden IP, but not Tor Browser-level anonymity".

### How it works
- **Install on request.** Settings → Private browsing → "Install Tor Browser":
  - downloads the official portable package from `dist.torproject.org`
  - checks its `.asc` signature against the pinned Tor Browser Developers key before running anything
  - installs it to `%LOCALAPPDATA%\NovaDM\TorBrowser`

  Or you choose an existing Tor Browser.
- **Open.** `Browser\firefox.exe --new-window <address>`. A second request reuses the running
  Tor Browser.
- **Connect automatically.** Tor Browser's own "Always connect automatically" option. Bridges are
  set up in Tor Browser's own connection settings.
- **Look.** A `userChrome.css` in Tor Browser's profile changes colours only (NovaDM dark/light and
  accent), keeping every size the same. This is browser-window styling that pages can't read.
  - Tor's community is split on whether *any* change is wise.
  - So there is a switch "Use Tor Browser's own look", and nothing else is changed (no `about:config`
    edits that pages could notice).
- **Ways in:**
  - Ctrl+Shift+N and menu "New private window (Tor)"
  - right-click a link → "Open in Tor window"
  - `.onion` links in normal tabs: offered in a Tor window, never looked up through DNS
- **Downloads in Tor windows** stay in Tor Browser (they must go through Tor). Its download folder
  is set to NovaDM's folder, so files land in the same place. NovaDM's engine is never used for
  them.
- **Updates.** Tor Browser updates itself (8–10 MB per update). NovaDM never patches its files, so
  it stays an official, signed copy.
- **Name and licence.** It's the unmodified Tor Browser, downloaded from the Tor Project and named
  as such. Nothing renamed or redistributed, so no trademark question.
- **NovaDM's own private tabs** (Chromium, no Tor) stay available as "Private tab without Tor".

### What it can't do
- **Separate app:** its own window and taskbar entry, not a NovaDM tab.
- **NovaDM tools don't work in it:** no ad-block, media button, grabber or Chrome extensions in Tor
  windows. Tor's design keeps it that way.
- **Slower start:** Tor Browser takes a few seconds to open, plus the Tor connection (usually 5–15 s
  the first time).

## 3. Tor-style hardening for normal tabs: measured impact

Method: an offline "fake web" (local proxy). Pages, ad blocking on, cache cleared before each load:
- a news page with web fonts, images, site script and a fingerprinting script
- a web-app page
- a WebAssembly page
- a page with two autoplaying videos
- a page with three cross-site frames

Each protection was applied from outside NovaDM's code (Chromium switches, DevTools protocol,
injected scripts), after warm-up loads; median of 5 loads, 5 separate NovaDM starts. Differences
under about ±10 ms are noise. Numbers are from this PC and local pages, not real sites.

| Feature | Function | Already implemented? | Before (ms) | After (ms) |
|---|---|---|---|---|
| Ad and tracker blocking | Blocks ad/tracker requests | Yes (0.1) | 779 load / 1062 CPU | 178 load / 29 CPU (1.1 benchmark) |
| Third-party cookies blocked | Embedded sites can't keep cookies | Yes (1.0) | 237 load | 238 load |
| Third-party storage partitioned | A tracker frame's storage is separate per site | Yes (Chromium default, verified) | — | 0 cost |
| Site isolation | Each site in its own process | Yes (Chromium default, verified) | 3-frame page off: 82 CPU, 497 MB | on: 233 CPU, 837 MB (security; keep) |
| Tracking redirects, tracking codes, de-AMP, HTTPS upgrade | Fewer hops and trackers | Yes (1.1) | — | saves a redirect per link |
| Fingerprint noise (Brave-style) | Canvas/WebGL/audio read-outs get tiny noise | No | 238 load / 25 fp script | 251 load / 42 fp script |
| Fingerprint block (Tor-style) | Canvas read-out blank, WebGL off, audio flat | No | 238 load / 25 fp script | 221 load / 15 fp script |
| Same values for everyone | Timezone UTC, en-US, CPU 4, memory 8, screen 1920×1080, no battery/USB/HID/serial/Bluetooth/network-info APIs | No | 238 load | 234 load |
| Remote web fonts blocked (Tor Safer) | Pages use system fonts | No | 238 load | 240 load (test fonts were small; real pages save their font download) |
| Click-to-play media (Tor Safer) | Audio/video only start when clicked | No | 255 load / 156 CPU | 95 load / 30 CPU |
| JavaScript JIT off (Tor Safer) | Scripts run interpreted (fewer exploitable bugs) | No | news 238 load / app work 71 / wasm 53 | news 549 load / app work 162 / wasm 733 (JIT off also turns off WebAssembly) |
| WebAssembly off | No wasm (sites fall back to JS) | No | 53 | not measured: the V8 switch had no effect in Electron; needs another method |
| JavaScript off (Tor Safest) | No scripts at all | No | 238 load / 106 CPU | 196 load / 46 CPU (most sites break) |
| Memory-only cache (Tor disk avoidance) | Nothing cached on disk | Private tabs only | repeat visit 199 | 237 (first visit after each restart) |
| Tor Safer-like set without JIT | Fingerprint block + same values + fonts + click-to-play | No | 238 load | 225 load |
| Not possible in Electron without patching Chromium | Bundled-font list, letterboxing per window step, reduced timer precision | No | — | — |

What the numbers say:
- **Free or faster, on by default (1.3):**
  - same values for everyone
  - device APIs off
  - WebRTC hiding local addresses (not measured; it only affects calls, not page loading)
  - fingerprint protection
- **Fingerprint protection levels:** "Standard" = noise (+13 ms on a page that fingerprints;
  canvas apps still work); "Strict" = block (17 ms faster, but canvas drawing apps break).
- **Click-to-play media** saves most CPU on video pages: an option, on in "Safer".
- **JIT off** more than doubles script time (app work 71 → 162 ms, news page 238 → 549 ms) and
  turns WebAssembly off, so it belongs only in a "Safer" level, as in Tor Browser.
- **JavaScript off** only in "Safest".
- **Memory-only cache** costs about 38 ms per repeat visit after a restart: private / Tor only.
- **Site isolation** costs memory but is a core protection: kept.
